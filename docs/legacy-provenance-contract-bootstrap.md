# Pure legacy provenance contract bootstrap

All eight PHP 8.2/8.3 portability CI jobs for the reviewed `53cf6297473bc31400a0777ff905bd79f1e65698` source failed `legacy-adoption-provenance.php` with `Class "Appliance" not found` at `inc/define.php:612`. The contract required Composer's autoloader and then the constants file directly. Composer declares only the `itsmng` namespace under `src/`; it does not resolve the legacy global `Appliance` class. The constants file calls `Appliance::getType()` when initializing the default impact types, before the pure provenance cases begin.

The contract now requires the standard `inc/based_config.php` entry point. That file loads `inc/autoload.function.php`, which requires Composer once and registers the existing legacy class loader, before loading `inc/define.php`. The global classes used by the constants file therefore follow normal application class resolution, and provenance still compares against the real application and schema version constants. No constants are mocked and no test-specific class catalogue is added.

This remains a pure provenance contract: it calls `LegacyAdoptionEligibility::proof()` with the original captured arrays. Every original acceptance/refusal case, diagnostic assertion, input-preservation assertion and output statement is unchanged. The selected bootstrap does not itself load `inc/includes.php`, `inc/db.function.php`, `inc/config.php` or a database configuration, open a database adapter, or start the application session. It retains the ordinary dependency/asset readiness check and local/downstream configuration support; it does not replace the normal configured runtime or claim that arbitrary downstream extensions have no side effects. Production eligibility rules, historical migration sources and populated adoption/refusal/retry contracts are unchanged.

The earlier compiler recipe parsed this file with `php -l` and discovered its name in the dynamic suite list. Neither operation executes its require statements. Offline entity mapping and the separately executed planning unit contracts also do not run this provenance entry point. Compiler success therefore did not validate its bootstrap.

Source review and the complete bootstrap-only inverse are the validation available for this change. ROOT still needs to execute the original pure contract directly with normal prepared dependencies, inspect its assertion summary and diagnostics, and run it in the complete portability order on both providers. Actual syntax/style checks and corrected runtime/CI results remain pending; a source-only fix does not make the prior eight jobs pass.
