# PDO MySQL owner and managed transaction admission

Status: source candidate only. No PHP, compiler, database, application, browser, TLS or CI test has run for this candidate. Frozen PostgreSQL234 is its immutable parent; existing history and lower-level raw PostgreSQL transaction contracts remain unchanged.

MySQL application and installation factories now create a PDO-backed owning DBAL wrapper. The current adapter, ORM, legacy statement/result and configured read connection share that supplied owner. Strict SESSION mode initialization and caller logging middleware survive reconnect; installation creation stays lazy. Native prepare, numeric fetching and nonpersistent distinct connections are explicit transport options.

Configured TLS key/cert/CA/CA-directory/cipher fields become real PDO MYSQL_ATTR_SSL_* options. Certificate/hostname verification is explicit, defaulttrue; false is represented only when explicitly configured. Unknown, malformed or conflicting driver/TLS options refuse before connect. A requested TLS connection must also report a nonempty physical Ssl_cipher before the driver is admitted. These source checks do not substitute for actual certificate/hostname/encryption tests; TLS infrastructure evidence remains required.

ManagedTransactionConnection::assertManagedTransaction compares physical PDO state with logical DBAL nesting inside the owner. DBAdapter delegates to the exact supplied connection. Unsupported capability, unknown native type and physical/logical disagreement refuse before frame acquisition; native failures preserve real DBAL exception conversion. PostgreSQL retains its separate aborted-commit check and raw-BEGIN compatibility. No application pg_*/mysqli calls, reflection, SQL keyword tracker or global relationship/state registry is added.

OwnershipUpdateUnit, DeletionUnit and the traced public/direct Transfer boundaries call the guard before model journals, notification barriers or owned frames. A caller's raw BEGIN/START is refused without committing, rolling back, adopting or changing its isolation. Normal managed nested savepoints remain supported. This entry check does not retrospectively undo raw hook COMMIT or prove same-depth transaction epoch identity; typed frame lifetime is a separate additive seam.

Prepared, unrun contracts exercise actual raw BEGIN/START with an uncommitted marker and independent observer, shared units/public Transfer refusal, unchanged depth/model/notification queue, aborted PostgreSQL raw state, managed savepoints, loss of physical transaction and reconnect, and unsupported-owner refusal. Actual PDO value tests cover native number/empty/duplicate metadata, legacy by-reference rebinding, null/literal UTF8/backslash, binary NUL bytes and a real DBAL LOB stream. Policy tests inspect lazy driver/TLS options without connecting or accessing configured TLS files.

Required gates: PHP/style/compiler; actual both-provider owner/refusal/value contracts; existing run.php/mysql-session-modes/postgresql-driver/postgresql-transactions; logger/reconnect/read routing; actual TLS good/bad certificate/hostname/socket behavior; fresh/populated upgrade/retry/idempotency/final schema and complete discovered suites on supported MySQL/MariaDB/PostgreSQL/PHP versions; applicable public application/API/browser/replica/CI. Supplied read endpoint source evidence is not live replica proof. Existing mysqli extension/tooling consumers remain available; this does not complete the overall legacy SQL/domain migration.

The separately appended frame-lifetime seam exposes ManagedTransactionConnection::captureManagedTransactionScope(): ManagedTransactionScope and DBAdapter convenience delegation. Capture happens only after a real owned DBAL layer begins. The opaque scope captures the exact original DBAL owner through a weak reference, the physical PDO identity through a weak reference, and a per-layer nonce minted by actual owner beginTransaction. Successful removal/replacement of that layer or close/reconnect invalidates it; balanced deeper managed savepoints preserve outer scopes. Scope assertions never expose PDO, maintain a global registry, parse SQL keywords, or reconnect a closed scope.

Prepared native scope tests use real owner begin/commit/rollback/close and the actual shared Ownership/Deletion/Transfer boundaries. They distinguish same-depth reopening on the same PDO from original frame continuity. Approval's own typed unit must additionally retain and check the exact supplied adapter/DBAL connection, preventing adapter replacement with another still-live owner; the transport scope cannot know which connection a caller's adapter currently references. Its integration remains an explicit dependency.

Direct raw SQL/native commit followed by raw BEGIN that bypasses the owner's APIs is unsupported and cannot be retrospectively undone. Entry refusal and typed owner frames do not claim to detect every such epoch replacement or reverse already committed data.


The additive MySQL command-lifetime correction gives the canonical driver connection ownership of all actual statements and results through weak handle registration. It delegates normal driver operations, including supplied logging middleware, and changes no SQL. Ordinary result free retains the driver's ordinary metadata/cursor semantics; physical owner close releases every retained statement/result handle even if one cursor reports a real failure. The DBAL wrapper resets its logical frames and facade close clears its reference in finally. Retained commands refuse instead of operating on an old writer or reconnecting it; the legacy facade also checks its exact originally supplied DBAL owner before binding.

The new unrun MySQL lifetime contract retains actual legacy/DBAL statements and even a freed ordinary result. It verifies a raw transaction marker is uncommitted to an independent observer, close rolls it back, a contended session advisory lock is released, and the physical PDO weak reference expires despite retained objects. Same-DBAL reconnect and actual public adapter rebind cannot revive old commands; already buffered LegacyResult rows remain readable. The original PostgreSQL234 driver and contracts are unchanged. External permissive/strict session-mode probes explicitly omit the managed wrapper declaration because they intentionally bypass the canonical owning middleware; their existing assertions remain unchanged.
