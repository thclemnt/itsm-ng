# Dropdown usage and model-managed Kanban boards

The final PostgreSQL portability run at `f3db6577c7324e04305c2a8cbbfbb4960ddf7c38` reported `dropdown-lifecycle.php` failing its expectation that a Project Kanban board blocks generic usage. Source inspection establishes that `ItemKanban::$items_id` declares `PolymorphicReference(Project::class, "itemtype", managed: true)`. `EntityRegistry::lifecycleRelations()` represents this model-owned cleanup as `_glpi_items_kanbans`, and `DropdownLifecycleRepository::isUsed()` intentionally excludes managed children. Project extends `CommonDBTM`; it is not a dropdown whose deletion should be blocked by its own managed board.

The corrected contract explicitly checks that metadata-derived underscore policy and that a matching board does not block generic usage. Real `KanbanRepository::load()` calls retain discriminator pairing under overlapping Project/ProjectTask identifiers and retain neighboring Project board identities. All other original assertions remain, including the negative overlapping-kind check and final foreign-key audit.

Generic usage still has independent positive and negative discriminator coverage. Current `ItemSoftwareVersion::$items_id` and `ItemSoftwareLicense::$items_id` each declare an unmanaged `PolymorphicReference(Computer::class, "itemtype")`; their software-owner associations are separately application-managed. The fixture creates real Software, version and license parents, Computer and Phone rows with colliding identifiers, and independent Computer neighbors. A Phone-only binding must not count as Computer usage; a matching Computer binding must count; a matching discriminator with a neighboring identifier must not count. Both subject families are exercised independently without changing entity metadata or schema constraints.

This fixture deliberately follows current ownership policy. The pending typed software subject modernization will make those links application-managed; its implementation must revise these explicit policy assertions and preserve generic discriminator coverage through another real unmanaged subject if one remains. The software owner has been notified. This test correction does not add production relationships or foreign-key guarantees to the current unconstrained software subjects.
