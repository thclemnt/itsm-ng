The failing relationship-lifecycle assertion therefore revealed actual public behavior, not just an outdated fixture.

Required native identity/deletion outcomes are checked so a hook that cancels the actual write cannot leave state attached to the purged source. The parent DeletionUnit, model journal, writer connection and notification barrier remain authoritative.

Cleanup identities and destination collisions use current pessimistic ORM reads inside that parent transaction, including a MySQL/MariaDB caller with an earlier repeatable-read snapshot. Source rows are ordered by ID. Standalone repository inspection remains readable without introducing a transaction. Native uniqueness still enforces later insert races; an absent-row query does not promise an insert lock, and the scalar Project identity is not a foreign key.

The relationship contract keeps generic ID/type-paired replacement coverage using the current automatic software installation reference. It additionally exercises actual Project purge/replacement: private board ID, payload, User, discriminator and creation date survive; shared residual cleanup and another type with the same numeric ID remain distinct; destination shared state and a neighboring Project survive. Collision, actual public update/purge veto, a canceled retarget write and later caller rollback retain the complete native graph. Existing authentication-source, recursion, virtual-asset, read-only and foreign-key assertions remain.
