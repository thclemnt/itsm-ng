The frozen `a736d72e03a41deee9723d39d50d372940ed1335` MariaDB full-suite run reached the final cleanup assertion in `domain-documents-schema.php`, then reported `Missing boolean domain CHECK: glpi_documents_items.glpi_documents_items_is_recursive_boolean` in `schema-check.php` and `identifier-sequences.php`. Later complete-schema guards also failed. These are recorded native results from the parent worker, not results of this source-only follow-up.

Doctrine DBAL table definitions retain the native PostgreSQL boolean type but do not represent the supplementary MySQL/MariaDB boolean CHECKs. Recreating a current table through `BaselineSchema` and adding only its typed-subject CHECK therefore loses the appended boolean domain while retaining the completed `20261008_boolean_domains` receipt. Replaying that completed migration is deliberately a no-op and is not a fixture repair.

`NativeBooleanFixture` snapshots only mapped boolean properties of the explicitly supplied fixture table. Property metadata identifies the domains; the native catalogue supplies their exact names, clauses, enforcement and column definitions. It requires canonical domains and a completed boolean receipt before reconstruction. Each reconstructed table must retain its original native boolean columns; restoration adds only missing captured CHECKs, rejects changed existing CHECKs, and proves exact native CHECK and receipt preservation. It never resets or writes the boolean receipt.

The document and operating-system fixtures use this boundary after each historical reconstruction and after final canonical restoration. This keeps their unrelated boolean domains intact while their own subject migrations remain deliberately pending, interrupted and retried. All original populated migration, native projection, foreign-key, comment, timestamp, invalid-data and final complete-schema assertions remain.

The source audit covered every `dropTable`/`DROP TABLE` site under `tests/database-portability`. Among fixtures that reconstruct current core tables directly, `glpi_documents_items` owns `is_recursive`, and `glpi_items_operatingsystems` owns `is_deleted`, `is_dynamic`, and `is_recursive`. Reconstructed appliance subject/recipient tables, project subjects, planning guest membership and aggregate-origin membership have no mapped boolean fields. Separate whole-database legacy adoption and canonical-history fixtures replay the full history. External disposable table drops do not reconstruct core boolean domains. Category, commercial-supplier and boolean-domain malformed fixtures already restore their explicitly owned native constraints and receipts.
