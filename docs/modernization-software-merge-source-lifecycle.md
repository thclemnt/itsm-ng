# Merge source removal owns its deletion lifecycle

At current 6f1, ROOT's unchanged-operation observer on both databases proved the public merge returned true while the required source-trash veto and actual pre_item_delete callback each ran zero times. PostgreSQL reached this failure in 189.140 seconds; MariaDB in 94.035 seconds. The original callback predicates and assertions stayed intact. The existing merge callback called putInTrash, which submits a public update and bypasses deletion hooks.

The merge-specific removeMergedSource command now uses the actual public Software::delete lifecycle before its ordinary follow-up comment/category update. SoftwareMutation owns the supplied canonical writer frame, model journal, session feedback and notification completion. Software::delete retains its existing assignment/hierarchy ownership and the shared deletion lifecycle, including pre_item_delete, deletion decision, mark-deleted storage, removal audit, post_deleteItem and item_delete. Refusal at either required operation cancels the entire enclosing merge; accepted callback work still runs inside the original caller frame and notification delivery waits for its physical commit. Selected source identity is immutable across both callbacks, and a refreshed mapped owning Software read verifies that the selected source remains deleted after completion callbacks.

The existing category-on-delete, raw is_deleted=1 and comment inputs retain their original ordering and ordinary lifecycle path. Thus existing pre_item_update hooks can still recognize the old trash request after the actual deletion lifecycle. The historical comment behavior is preserved exactly: a conditional newline followed by the supplied merge comment, rather than concatenating the old comment. Dictionary putInTrash and its actual RuleDictionnarySoftwareCollection callers remain byte-exact and retain their update policy. Public merge arguments and progress callbacks, mapped version collision and ownership moves, aggregate refreshes and the original merge controls remain intact. No SQL or type registry is added.

Template sources are explicitly ineligible for this merge removal command because the normal public deletion lifecycle force-purges templates. The merge coordinator checks the current entity-owned template flag under its existing selected Software locks before assignment writes, version moves or aggregate/deletion callbacks. Direct removal also refuses templates. This is a compatibility boundary: template merge policy needs a separate domain decision; the command cannot silently turn a former mark-deleted update into physical purging. Source actor eligibility beyond the current MassiveAction destination UPDATE admission remains OPEN; this change does not invent a generic repository can() or bypass context.

The new focused contract exercises actual standalone and caller-owned frames: early delete veto, follow-up update veto, post-delete identity substitution, same-writer completion restoration, callback primary propagation, accepted ordering/category/comment/delete history, unrelated source preservation, unchanged dictionary behavior and template parents/children/audit preservation. All original Software/Transfer/atomicity contracts and frozen entities/history are unchanged. No callback is faked merely to increment a veto counter.

SOURCE-only implementation; author has run no PHP/compiler/native jobs. ROOT must independently review and compose the shared DeletionUnit ownership changes, compile the final source and run the new focused contract plus original software and software-assignment-atomicity contracts on both providers, preserving the 300-second budget, rows, models, caller frames, notifications and final schema. Both complete portability suites remain required before a current milestone. Raw unmanaged transaction epoch limitations, broader actor/scoping/merge concurrency, and separate future component 20/1080 validation remain OPEN.

A source-reviewed extensible boundary also pins the supplied adapter, DBAL connection and any already-active managed scope before Software’s overridable preload. A real subclass and a separate canonical writer exercise initial/nested preloads; an actual delete completion callback exercises the follow-up boundary. These are source controls, not observed foreign-owner writes on the standard merge path. No new epoch tracking is introduced; arbitrary foreign plugin writes, deeper generic callback adoption, interactive authorization and raw native transaction replacement remain open.
