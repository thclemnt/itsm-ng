# Configured CLI installation owns its write adapter

Source-only batch based on `741fb2b1f0`. No native installation, database, TLS, browser or application execution has been performed for this repair.

The console application constructs the configured `DB` subclass before executing `db:install`. The previous command decoded its password, extracted four basic fields, then opened another adapter through the constructor-bypassing factory. This discarded separate PostgreSQL `dbport`, `dbschema`, `dbsslmode` and TLS settings, and MySQL TLS material and charset. MySQL also opened a server-level connection to rediscover an already connected target database. Inline host ports surviving that path did not prove separate PostgreSQL-port preservation.

The existing-config path now retains that exact connected write adapter after confirmation. Absent, disconnected or read adapters refuse before catalogue/DDL access. PostgreSQL installation keeps its empty-schema/resume checks and passes the supplied writer into the existing installer. MySQL skips provisioning for that already connected named database and preserves existing-table, force, retry-journal, encryption-key, schema and status behavior. Neither branch closes or reconnects the caller's adapter. Read-connection selection is unchanged. There is no new connection configuration catalogue and no invented MySQL `dbport` property.

Fresh basic-input configuration and `--reconfigure` still use their original provisioning/factory paths. Those branches select the requested provider rather than relying on the formerly loaded `DB` subclass. Password encoding/decoding is unchanged there; existing-config installation no longer transforms a password at all. Configured public properties and the already selected physical endpoint remain owned by their original adapter.

The prepared `installation-writer-ownership.php` contract invokes the actual install execution body against a complete disposable schema. It preserves the existing-table refusal, checks object and physical-handle identity even when reconnect-only endpoint/password properties are deliberately unusable, refuses absent/disconnected/read adapters, and retains confirmation-abort and explicit-input guards. Configuration bytes, complete ledger state, all configuration rows, schema and connection idleness must survive. It uses no force/reset/install DDL. This direct execution test does not substitute for whole-console initialization or a fresh CLI installation.

The external native packet requires separate PostgreSQL before/after databases with a non-default separate port and an owned non-public schema. Both start empty; actual `bin/console db:install` must be observed with exact source/config/private-var routing. Native namespace, all canonical receipts, sequence ownership, public-schema preservation, completed-install refusal and interrupted-install retry must be proved. Both provider contracts, relevant installation/history/initial-data/cache/strict-session suites and a coherent complete portability matrix remain required. Live TLS verification, mutual TLS, charset/socket transport and real replica validation are separate gates; plain local tests cannot establish them.

Remaining architecture work: replace the partial reflection factory through provider-owned configuration and normal construction; preserve complete settings when CLI configure/reconfigure saves a file; update web preflight/provisioning/save and manual/auxiliary `createConnection()` callers. The overall modernization goal remains open.
