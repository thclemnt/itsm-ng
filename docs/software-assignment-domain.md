## Public mutation boundaries

The default CommonDBTM add/update/restore completion sequence is preserved behind protected prepared-persistence hooks. Models opt into a software command after final update identity/endpoint guards, without replaying preparation, public hooks, uploads, or unicity checks. Existing ownership forwarding still runs through its own required-write unit.

`SoftwareAssignmentService` owns writer locking, eligible allocation counts, quantity decisions, and required licence-to-Software validity writes. Its repository uses meaningful owning associations and the supplied writer. Presentation selectors retain their own scoping/read-routing policy. Eligibility counts are global consistency counts, exclude deleted allocations and deleted/template subjects, and include each independent duplicate allocation. Software validity still includes invalid licences in trash, templates, and other entities. Negative capacity (normally `-1`) is unlimited; finite over-allocation is permitted and represented by invalid aggregate flags.

A public allocation add, actual reassignment, inventory lock, restore, soft deletion, or purge must complete its required old/new licence and owning Software updates. The six mapped assets join the same boundary for eligibility/scope changes, deletion, and restoration, including installation-owned Software parents when no licence allocation exists. Actual licence quantity or owning Software changes also reconcile the affected aggregates. Final callback cancellations, net-zero writes, and input-only changes do not create discarded-parent aggregate work. Required indicator commands verify persisted writer state even when a callback returns success after dropping its write.

The common journal restores shallow `fields`, `input`, `updates`, and `oldvalues` states of actual participating model instances on failure. Standalone prepared commands retain attempted input for diagnostics; Transfer's enclosing journal retains its earlier operation state. This does not rewind private/plugin state, external effects, or a successful model automatically when its caller later rolls back. The common notification barrier preserves nested merge/cancel and sends only after physical commit; releasing a caller savepoint leaves queued delivery pending.

Transfer selects installations/allocations with typed ORM queries and requires their actual public update/delete lifecycles. A required nonpositive version/Software copy cancels the operation; the direct missing-source version helper retains its established `-1` contract. Licence transfer decides quantities under writer locks: finite destinations increase by one, unlimited destinations remain unlimited, finite sources above one decrease, and the last finite source is trashed only after successful reassignment. Zero/unlimited sources keep their quantities. A newly created destination licence starts at one, including an unlimited source, preserving existing behavior. Separate buy/use versions, literal name/serial matching, and duplicate allocation multiplicity remain relevant.

Public Software merge retains its deliberate bulk version/licence operations and installation-collision policy, but requires old/new Software validity before source trashing within the common outer journal/notification frame. Dictionary licence ownership move uses a bounded equivalent command and replay requires its acceptance before later version/trash work. This does not make an entire dictionary replay atomic.

## Isolation and retry

The supplied physical connection is authoritative. No command changes the caller's isolation. PostgreSQL allocation commands admit READ COMMITTED (and PostgreSQL's equivalent READ UNCOMMITTED) and refuse REPEATABLE READ/SERIALIZABLE before their first software-command write, preserving the caller frame and issuing a retry-outside-transaction diagnostic. PostgreSQL stronger snapshots cannot see later allocation phantoms even through locking reads; a shared writer alone cannot make these snapshots current. An enclosing Transfer may already have performed asset/Infocom work before its software module is reached; rejection rolls back that enclosing frame. This is not a first-write admission guard for every Transfer family.

MySQL/MariaDB repeatable-read commands use current ORM locking row projections for ownership, eligibility, membership, and required aggregate postconditions. A plain aggregate COUNT or ordinary ORM refresh would still reuse an older caller snapshot. The current count reads eligible row identities; no aggregate or DISTINCT locking query is used. Captured actor/subject contexts and final ownership are rechecked under locks. A direct licence command also compares its loaded canonical row against the current locked row, deriving that row from entity metadata and preserving null distinctions. Any concurrent persisted change refuses that prepared command, protecting its prior actor/scope decision and audit baseline rather than silently reloading different state. This optimistic baseline intentionally also requires retry for unrelated concurrent licence changes. The installation retains its model-owned pure final subject decision so generated cache values are distinguishable from permitted explicit same-owner synchronization.

The domain lock order is Software owners, licence IDs, current allocation rows, then the complete set of subjects influencing those counts, with stable ordering at each step. Asset eligibility and Transfer discover membership before these locks and refuse newly discovered unlocked parents before writing. Bulk merge/dictionary ownership changes acquire the same graph. Independent final source review and real concurrent-provider contracts remain pending. Native deadlock/serialization failures must roll back the owned unit, preserve caller ownership, and retain their actual exception semantics. No automatic retry of a caller's whole transaction is promised. Known model, aggregate, history and queue tables are checked for transactional MySQL storage before writes; this is not a guarantee for arbitrary plugin tables or external effects.
