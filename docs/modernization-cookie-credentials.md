# Owning cookie credential outcomes

`User::getAuthToken('cookie_token')` now verifies the generated hash and requested issuance timestamp together after the complete public update lifecycle. `UserRepository::cookieCredential()` selects both owning User properties in one fresh ORM query on its supplied connection. Its immutable `CookieCredential` result compares the hash byte for byte and the mapped datetimetz instant, including timezone-equivalent representations. Managed ORM/model fields cannot establish this persisted outcome.

The timestamp is captured before callbacks. An accepted `pre_item_update` callback can remove the date, or an accepted `item_update` callback can restore a NULL/expired date. If either persisted part differs, the producer returns false without undoing accepted writes, hooks or audit history. Ordinary password login remains admitted and emits no new remembered credential. Personal/API generation keeps its existing stored-token admission; this change adds no cookie expiry policy to those fields and changes no reuse/expiry rules.
