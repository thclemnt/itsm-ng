# Initial writer capability for model-owned lifecycle commands

CommonDBTM exposes a protected `captureLifecycleWriter(DBAdapter $writer): void` hook at the start of public add/update, after the existing slave refusal and before row loading, clone delegation, journal checkpoint, plugin callbacks and preparation. Its default is empty. It does not grant rights, choose a connection, start a frame, change public return types, replay callbacks or enforce a global writer policy.

An owning model can keep the supplied writer privately and compare it at the existing normalization, validation and prepared-execution boundaries. Capturing only inside executePreparedAdd/Update would miss an earlier pre_item_add/update substitution. Capturing only from a loaded row would miss add. Models remain responsible for final authorization, actual scope, transaction capabilities, nested child refusal, lifecycle notifications and meaningful transient-state checkpoints. The existing OwnershipUpdateUnit and typed Connexity finalizer remain the owners of their established operations.

The focused lifecycle-writer-capture.php contract uses real authenticated public Supplier and typed Item_OperatingSystem models, actual registered pre/item hooks, real queue writes and existing ownership frames. It proposes checks for initial callback/load order, a same-physical-connection alternate adapter, no-write false veto, exact thrown callback identity, parent-owned native/history/queue rollback, same-instance retry, generated typed compatibility identity and unchanged default plugin behavior. The alternate adapter is deliberately not a second live database or replica proof.

This batch is SOURCE preparation only at76cd. No PHP syntax, focused native, full portability, application, API or browser execution has been performed for it. It introduces no schema/seed/history changes and does not complete network parent typing or aggregate retargeting.

The next network batch must resolve Enclosure/PDU/Cluster's absent explicit NetworkPort forwarding with real populated-row evidence, preserve registered plugin and free/direct Name roles, own nested subtype/Name/Address/cable outcomes, and restore model-owned IP calculator/transient payload state only after proven rollback. Port/Name forms currently ignore update(false) before Event logging and need explicit refusal acknowledgement. Typed relationships, historical data repair, locking/isolation behavior and full both-provider validation remain open.

An arbitrary plugin's writes or external effects inside the callback itself are not made reversible by writer capture. The hook can prevent subsequent owned core persistence on a substituted writer; it cannot authenticate historical completion, restore arbitrary plugin internals or claim external notification delivery. Restore/purge and direct DBAL commands are outside this initial add/update hook's scope.
