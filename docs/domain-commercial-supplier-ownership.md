# Domain commercial supplier ownership

Prepared on `th/exp/postgres-domain-supplier-ownership`, initially based on `525075411163869601c2dbfb762d74352761e021`. This batch is source-only pending a shared validation window. No database, installation, vendor-copy or browser job has run in its isolated worktree.

The direct `Domain.suppliers` association is the commercial supplier inherited from the historical Domains plugin. Its financial supplier remains `Infocom.suppliers`; this change does not modify that role.

The authoritative directional ownership rule lives on the Doctrine Domain entity: an assigned commercial Supplier must belong to the Domain's owner entity, or the Supplier must be recursive and its owner must be an ancestor of the Domain's owner. The rule traverses actual `Entity.parent` associations, includes root ID zero and diagnoses cycles. Domain recursion does not authorize a sibling, descendant or nonrecursive ancestor Supplier. No detached relationship registry, table-name switch or global boolean type policy is added.

`DomainRepository::assertCommercialSupplierAssignment` assembles the effective owner/association without modifying a managed record, using the caller's EntityManager. Public Domain preparation invokes this preflight through `Orm::create($DB)` before Domain persistence/history. The current importer reuses it for the commercial role. Doctrine PrePersist, PreFlush and PreUpdate callbacks invoke the same entity predicate using the actual event EntityManager, providing a backstop for direct ORM writes and post-prepare mutation. PreFlush also checks a newly persisted object changed before flush. They do not replay public hooks. Frozen historical importer policy remains independent of current entities.

MySQL's persisted BOOLEAN can contain the legacy value `2`, which Doctrine hydrates as true. A purpose-specific bound ORM predicate accepts only actual stored false or true before using that hydrated flag; non-boolean or absent Supplier records receive a diagnostic. Pending canonical Supplier insertions have a typed boolean and can be used in the same unit of work. No global type replacement or schema change is involved.

Supplied nullable values and absent keys have distinct meanings. A supplied null or legitimate legacy empty selection clears the optional commercial supplier; an absent key retains it on update. Association scalars use the existing LegacyValues decoding before property-derived ReferencePolicy normalization, preserving uppercase/lowercase NULL tokens and rejecting escaped literal NULL as an identifier. Owner-only changes validate the retained Supplier. Simultaneous explicit clearing can permit a coherent owner move. Cloning follows the same public add path and respects explicit null overrides.

The scoped Supplier choice is issued under Domain authority. Historical/current source does not require separate Supplier READ or UPDATE merely to select it, so this repair adds neither. Existing Domain CREATE/entity authority remains at the public caller; proposed actor authorization for existing Domain owner retargets is a distinct pre-existing boundary and is not silently changed inside trusted lifecycle methods or ORM callbacks.
