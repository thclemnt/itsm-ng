# Native call inventory ownership

ROOT's original e658 required inventory contract failed because lexical discovery found two PDO calls, in the owning PostgreSQL Doctrine driver's concrete prepare and query methods. The scanner mistook these transport implementations for application persistence. The original failed receipt remains retained. Its checkpoint was 2 lexical native calls, 2844 legacy adapter sites, 8 adapter constructions, 35 adapter-internal calls, 28 dynamic candidates and 839 method candidates; these source figures are not an ORM completion claim.

Lexical scan() preserves the original call locations and categories. Repository discovery adds a narrow semantic classification: the native instance call must use the actual $this property inside its matching concrete query/prepare method, whose actual loaded declaration comes from that exact physical source file and implements Doctrine\DBAL\Driver\Connection. The property must belong to that declaration and have the native PDO type. No class is constructed or database opened. Paths, class-name conventions, source strings or a PDO receiver alone confer no exception. Static native calls, constructors, free native functions, unproven property types and application calls remain direct-native evidence. Classified driver calls retain their locations plus the authoritative class/interface/method/property proof.

The required assertion now refuses every remaining core application direct-native call, including PostgreSQL calls previously exempted by a prefix check. Existing comments/string/declaration, multiline/offset, dynamic receiver, adapter and application-family checks remain. New controls inspect the real driver declaration and reject a forged path, wrong physical file and changed source bytes. No tests or warnings are suppressed and no production transport/schema is changed.

This is static source admission, not whole-program type inference or runtime driver validation. Imported aliases, alternate variables, callbacks, generated code, dynamic methods and external plugins still require semantic discovery. Thousands of legacy SQL paths remain. ROOT must compile and run the required inventory contract at the actual composed source, inspect the resulting ownership categories, then complete both coherent database/application suites. SOURCE author runtime remains UNRUN; modernization remains OPEN.
