# Disposable portability database ownership in CI

This source-only proposal is based on ea2d298c82e383989cf47b66129135d68c4c43db and the recorded PostgreSQL14/MariaDB11.8 failed CI excerpts. No YAML execution, provider connection, native contract, compiler or remote CI ran while preparing it.

The existing service initializes only `itsm_port_ci` for role `test`. Earlier workflow steps explicitly provision history, cache, projection-reference and legacy-session databases. The full discovered suite also requires a separate pre-existing `itsm_port_software_subjects`; both recorded providers stop its migration contract at the explicit provisioning assertion. The proposal creates that empty dedicated database on both providers.

Five other Maria contracts deliberately assert absence and create/drop their own private database. They must retain that ownership boundary: the workflow grants access without precreating them. Domain tests use exact `itsm_port_ci_domain_schema` and `itsm_port_ci_domain_adoption` names. Entity, Notification and authentication-source tests allocate under `itsm_port_entity_parents_`, `itsm_port_notification_targets_` and `itsm_port_authentication_sources_`, followed by PID/random suffixes. The grants contain escaped literal underscores and a single trailing wildcard only for those three dynamic namespaces. A quoted shell heredoc preserves the intended database-pattern bytes.

The role gets no server-wide grant. Its database-scoped grants permit the fixture's actual CREATE, canonical install, DML, inspection and DROP operations. PostgreSQL's service test role already owns database creation; only the separate software database is missing there. Config/key setup remains the normal parent install and each contract's existing child ownership mechanism. The public MySQL web-install lane retains its existing separate root role.

Before integrating or claiming this candidate fixes CI, ROOT must validate database-pattern grant semantics on official MySQL8.4 and MariaDB11.8. In particular, inspect MySQL's actual partial_revokes setting: database wildcard grants have different meaning if it is enabled. Do not disable that server setting merely to accept the patch; if the official service differs from its ordinary default, prepare explicit supported fixture namespace configuration instead. Prove allowed names can be created/dropped and a disjoint name is denied, then run the unchanged original contracts. Tests must still prove target absence before their CREATE. No global privilege, precreated dynamic fixture, skip or runner exception is an acceptable substitute.

The discovered full suite and its original300-second per-contract budget are unchanged. This candidate addresses missing database/grant setup only. It does not fix component fixture collisions/stock admission, PostgreSQL Software atomicity timeout, MariaDB11.8 generated readback or native1020 current-read behavior, the Migration query-mock assertion, lint, missing original-key migration fixtures, or MySQL8.4 schema inspection. Those recorded failures remain distinct and require their own evidence.
