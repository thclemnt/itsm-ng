# Migration configuration lifecycle test

The recorded ea2 Maria unit run has one failure in `Migration::testAddConfig`: its mock captures one legacy lookup where the test expects nine legacy Config/audit SQL calls. `Migration::addConfig` still queues first-registration-wins values by context. `executeMigration` calls `storeConfig`, which excludes already stored names and invokes the actual `Config::setConfigurationValues` public lifecycle for missing values. Config and Log persistence now use mapped writers, so the old query recorder cannot establish their behavior.

The original named test now uses the configured writer in an owned managed transaction while keeping the Migration output observer. It preserves the three original cases: two missing values, the same names in a different context, and only one missing value alongside a stored value. It verifies actual public Config readback, independent context rows, corresponding audit names/values/owner/action/date and output messages. Additional controls prove first registration wins, persisted values cannot be overwritten by a repeated migration, an empty queue adds no records/history, and unrelated rows remain exact. Rollback restores original Config/audit rows and transaction depth; private random fixture names are not configuration reset or manual schema reconstruction. The Migration class restores its configured global writer after each existing legacy query-mock method so method order cannot redirect the real lifecycle test.

`Migration::addConfig` remains a public extension/legacy migration utility. Historical scripts call it, but canonical upgrade coordinators do not start those older scripts against current schema. This test does not authorize an unsupported legacy upgrade or modify canonical history.
