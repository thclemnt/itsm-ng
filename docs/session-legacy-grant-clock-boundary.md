# Legacy grant inspection and the session clock

The missing-grant-table contract logs in against the installed database, then connects a separate empty database before calling `Session::initEntityProfiles()`. PostgreSQL connection setup calls `setTimezone()`, which refreshes `glpi_currenttime`; MariaDB connection setup does the same when database timezone support is available. Login and auxiliary connection setup can span a second boundary.

The contract retains the session captured after login for its user identity, original grant snapshot, and final restoration. It captures a second complete session after auxiliary setup and writer inspection, immediately before testing grant initialization. A separate complete-session assertion allows setup to change only the clock. Missing-table initialization and its repeated call must still produce exactly that second snapshot with an empty `glpiprofiles` value. Returning to the installed adapter and repeating the refresh must reproduce the complete second snapshot.

This correction changes the fixture's measurement boundary, not application behavior. It preserves every original assertion, the dedicated empty-database controls, supplied writer identity and transaction depth, and full final restoration. It neither forces timestamps nor excludes the clock from the read-only initialization assertions.

On source `fb279467b39c5b486dc303e137583120a710860a`, root ran the original assertions through separate observation-only copies on PostgreSQL and MariaDB. Natural runs passed when login and auxiliary connection setup shared the same clock value. A separate diagnostic copy delayed auxiliary setup by 1.1 seconds and reproduced the original complete-session assertion failure on both providers. The complete setup-session difference contained only `glpi_currenttime`; the complete initialization difference from that setup snapshot contained only `glpiprofiles`. Both failed diagnostic runs restored the original session, supplied writer, and transaction depth. Tracked source and configuration were unchanged. The repository contract contains no delay or forced timestamp.

The observations are recorded in `session-legacy-snapshot-fb279-{pg,mysql}-{natural,second-boundary}.json` and the corresponding logs under the cloud evidence directory. They prove the second-boundary defect in the original fixture; they do not substitute for execution of this corrected contract. Corrected PostgreSQL/MariaDB execution, static PHP checks, and the subsequent complete suites remain pending root validation.
