# Entity-owned tree keys and indexes

Source-only implementation on `th/exp/postgres-tree-schema-ownership`, based on `ea2d298c82e383989cf47b66129135d68c4c43db`. Integration is held until the current combined twenty-version history batch finishes coherent validation. No PHP/interpreter, compiler, autoload, application bootstrap, native database, installation, assets or browser job has run in this isolated worktree. `git diff --check` passes; independent source review found no blocker. Runtime equivalence remains an acceptance requirement.

BusinessCriticity, DocumentCategory, KnowbaseItemCategory, Location and State now own their generated parent identity and physical indexes beside their mappings. `ReferenceKey` supplies the explicitly selected parent column's quoted `COALESCE(parent, 0)` expression. The existing ORM column declaration retains nullable BIGINT, generated ALWAYS and insert/update exclusion. `SchemaIndex` supplies one declaration of physical name, ordered columns and uniqueness; PostgreSQL's distinct physical name is explicit in each entity. Location and KnowbaseItemCategory also declare their exact one-column entity-ownership supporting indexes. No runtime table catalogue or parent-name heuristic is introduced.

The custom AttributeDriver projects these declarations into real Doctrine metadata, including SchemaTool input. Its provider-specific configuration cache already separates platform classes and serialized metadata factories. The current BaselineSchema projection replaces only explicitly owned indexes and ReferenceKey fields used by those indexes. Other generated compatibility subjects keep their existing metadata-derived builders; Dashboard's ReferenceKey declarations are unaffected. The old runtime invocation of `TreeUniqueness::TABLES` is removed. Historical TreeUniqueness, TreeParentReferences, baseline, migration history, ledger/version definitions, snapshots and replay callers remain byte-for-byte unchanged. No installation DDL or new migration version is added; this must be proved to preserve the installed schema before integration.

Consumers still include the read-only SchemaCheck and CLI command, canonical History's final convergence check, Upgrade's historical/current retained-column prerequisite, metadata/inventory checks, and subject fixture restoration. The checker has no repair path. This change does not replace frozen installation history with current entity generation.

The new unexecuted `tree-schema-ownership.php` contract checks actual installed and SchemaTool/current index names, ordered uniqueness and two supporting indexes; nullable native BIGINT and stored generated expressions; read-only ORM inserts/updates with refreshed generated values; real entity owner zero versus nullable parent/root key zero; rejected root duplicate/null reassignment and nonexistent zero-parent FK writes with native row preservation. It deliberately changes one installed owned unique index to a nonunique index, requires schema checking to report the drift and leave it intact, and restores the exact original index and native rows. Tests use dedicated `itsm_port_*` databases and restore their DDL in `finally`; these destructive checks need an isolated database validation slot.

The existing unchanged tree-parents contract remains authoritative for public root/child creation, rename, move, cycle refusal, purge/replacement, cache admission/invalidation, historical invalid-data diagnostics, replay retry and idempotency. Tree transaction/cache and unchanged functional tree/application classes must also run. Adding another copy of those public-flow tests would not strengthen this batch.
